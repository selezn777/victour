# План реализации ВикТур (VicTour) — от нуля до запуска

Основа: `docs/VicTour_tours-and-prices.md`. Стек выбран по аналогии с Asia Mix / EcoVoyage
(Next.js + Supabase + Vercel) — уже знакомый и рабочий, не нужно осваивать новый.

Работа стартует блоками по правилу проекта: один блок за раз, вопросы перед правкой,
явное «делай» перед началом. План ниже — последовательность блоков, не однократный спринт.

---

## Фаза 0 — Решения и заготовки

- Стек: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui.
- БД: Supabase (Postgres) — отдельный проект, отдельно от Asia Mix/EcoVoyage.
- Хостинг: Vercel, отдельный проект.
- Домен: временный `*.vercel.app` на старте; публичный домен VicTour — отдельное решение позже (пункт брифа "не решено").
- Календарь гида на MVP — **не cal.com/cal.diy**, а простая таблица доступности в Supabase
  (один гид, ручное подтверждение — незачем поднимать целый self-hosted продукт под одну персону).
- Репозиторий: новый GitHub-репо (по аналогии `selezn777/VICTOUR`), git уже инициализирован локально в `~/Downloads/viktur-app`.

**Результат фазы:** пустой Next.js-проект, подключённый к Supabase и Vercel, задеплоенный "hello world".

---

## Фаза 1 — Данные и контент

- Схема БД: `tours` (5 записей — Нячанг, Маяк, Северные острова, Хон Там, Далат), `pricing_tiers`
  (цена по числу гостей 2–8, отдельно взрослый/ребёнок где нужно), `guides` (на старте один — Виктор),
  `guide_availability` (даты/статус: свободно/занято/отпуск), `bookings`, `booking_items` (тур+дата+гости
  внутри одной заявки — для пакетов), `surcharges` (Камрань/Amiana доплата).
- Загрузка утверждённых цен и маршрутов из брифа в БД (никаких новых цифр — только то, что уже зафиксировано).
- Логика скидок и курсов как чистые функции (не хардкод в UI): пакетная скидка 5/10/15%, курс $1=26000 VND,
  наценка ~8% на RUB — с возможностью поменять курс без деплоя (админ-поле, не код).

**Результат фазы:** данные туров и цен живут в БД, а не в JSX; расчёт скидки/валюты — тестируемая функция.

## Фаза 2 — Главная страница

- Первый экран: полноэкранный визуал салона, тёмная подложка, заголовок «Вьетнам такой, каким вы хотите
  его видеть», объяснение "больше гостей — дешевле", блок 5%/10%/15%. Один статичный кадр, без карусели.
- Компактный хедер: лого, поиск, избранное, тема, бургер-меню, курс $1=26000 VND + RUB.
- Каталог: 5 карточек туров (фото, обещание, длительность, цена "от", текстовая кнопка).
- Мобильная раскладка сначала (hero в один экран без вертикального скролла, карточки в одну колонку).
- Без графических стрелок — только текстовые/иконочные кнопки без "→".

**Результат фазы:** рабочая главная страница, соответствует разделу «Требования к сайту» брифа.

---

## Фаза 3 — Страницы туров (5 штук)

- Общий шаблон страницы тура: описание, маршрут по пунктам, что входит/не входит, таблица цены по гостям,
  фото, выбор гида, выбор даты, кнопка "Добавить в заявку".
- Для Далата — блокировка сразу двух календарных дней и таблица билетов/опций из брифа.
- Индивидуальные данные каждого тура заполняются из БД (Фаза 1), не хардкодятся в компонентах.

**Результат фазы:** 5 живых страниц туров с реальными маршрутами и ценами.

---

## Фаза 4 — Пакетный конструктор и бронирование

- Конструктор: выбор 2–4 туров, своя дата на каждый, авторасчёт цены со скидкой, подсказка "тот же гид на
  все дни", отдельный показ доплаты Камрань/Amiana (не скидируется).
- Форма заявки: тур(ы), гид, дата(ы), взрослые/дети, отель (обязательно), имя, канал связи
  (WhatsApp/Telegram/MAX/ВК), пожелания, способ предоплаты.
- Календарь показывает только свободные даты выбранного гида; защита от повторного бронирования той же даты.
- После отправки — статус "Проверяем доступность", ручное подтверждение (MVP, без автоматики).

**Результат фазы:** гость может собрать пакет, увидеть цену и оставить заявку одним потоком.

---

## Фаза 5 — Доставка заявок и мини-админка Виктора

- Реальная доставка заявки: сохранение в БД + отправка уведомления в Telegram/WhatsApp (не просто deep-link).
- Простой список заявок для Виктора: подтвердить / предложить другую дату / отклонить.
- Подтверждение вручную помечает даты гида занятыми — сразу видно в календаре гостя.
- Без ролей, кабинетов партнёра и сложной CRM на этом этапе (прямой пункт брифа — "без сложных кабинетов").

**Результат фазы:** Виктор получает заявки не в почту/руками, а в рабочем списке, и подтверждает их за пару кликов.

---

## Фаза 6 — Оплата

- Подключение приёма предоплаты (30%, не менее $80) — способ оплаты выбирается отдельно (нужно решить провайдера:
  для VND/USD/RUB одновременно вариантов немного — отдельный вопрос перед началом фазы).
- Фиксация итоговой суммы в выбранной валюте на момент подтверждения (курс "заморожен" для этой заявки).
- Логика отмен и возвратов по правилам брифа (полный возврат заранее, удержание $80 при отмене <24ч).

**Результат фазы:** гость может внести предоплату онлайн, а не только по договорённости.

---

## Фаза 7 — Контент и доверие

- Блок «Отзывы гостей о Викторе» с честной ссылкой на исходную Google-карточку (не выдавать за отзывы бренда).
- FAQ: питание, дети, Камрань/Amiana, отмены, погода, способы оплаты.
- Фото/видео: минимум один сильный кадр на тур (для Далата — Samten Hills), видео салона для хедера/героя.

**Результат фазы:** сайт перестаёт быть "пустым каркасом" и обретает доверие/контекст.

---

## Фаза 8 — Проверка перед запуском

- Прогон операционного чек-листа брифа: реальное время маршрутов, часы работы точек, актуальные цены,
  подтверждённый транспорт и лимиты гостей.
- Сверка новых тарифов Boss Luxury с текущей экономикой каждого тура.
- Проверка адаптива на реальных телефонах (не только DevTools): hero в один экран, формы в одну колонку.
- Проверка на дубли/двойные бронирования, проверка расчёта скидок на граничных случаях (2/3/4 тура, Далат как одна экскурсия).

**Результат фазы:** сайт готов к первым живым продажам, а не только к демонстрации.

---

## Фаза 9 — Запуск

- Публичный домен VicTour (решение отдельно, пока технический адрес временный).
- Реальный курс RUB (не захардкоженный) — либо ручное обновление Виктором, либо API курса + наценка 8%.
- Партнёрская карточка (для будущих турагентов/консьержей) — цены, что входит, комиссия 15%, но без личного кабинета партнёра на старте.

**Результат фазы:** публичный запуск с реальным доменом и рабочим приёмом заявок/оплаты.

---

## После запуска (не входит в MVP, но заложено в архитектуру)

- Личные календари нескольких гидов (не только Виктора) — карточка гида, языки, стиль, доступные даты.
- Кабинет партнёра с расширенными статусами заявок.
- Южные острова как партнёрский продукт — карточка после проверки условий оператора.

## Порядок работы по фазам

1. Перед каждой фазой — короткое согласование (что меняем/сохраняем/критерий успеха), как в правилах проекта.
2. Работа начинается только после явного «делай».
3. После фазы — показывается опубликованная версия, фиксируется как «утверждено», следующая фаза — отдельной правкой.
